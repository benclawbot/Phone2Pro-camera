# Nothing Camera Static Routing Index

Status: implemented for CAM-022, CAM-024, CAM-026, CAM-027, CAM-028, CAM-029 and CAM-030.

`tools/apk/build-routing-index.py` ranks files in a local JADX/apktool analysis run by their relevance to the stock Expert 0.6×/1×/2× route.

It complements the broad keyword report generated by `tools/apk/analyze-nothing-camera.sh`. The broad report finds every literal occurrence; the routing index groups those occurrences into semantic signals and prioritizes files that bridge the lens UI to Camera2, session, vendor/SAT or JNI operations.

## Run

First analyze the matching base and split APKs:

```bash
chmod +x tools/apk/analyze-nothing-camera.sh
tools/apk/analyze-nothing-camera.sh \
  --output nothing-camera-analysis \
  /private/path/to/camera-apks
```

Then build the ranked index. The supplied path may be one analysis run or its parent directory; the newest run is selected from a parent directory.

```bash
python3 tools/apk/build-routing-index.py \
  nothing-camera-analysis \
  --json nothing-camera-analysis/routing-index.json \
  --markdown nothing-camera-analysis/routing-index.md
```

Keep these outputs with the controlled local analysis bundle. The index contains short derived line snippets and file paths; review it before sharing because obfuscated identifiers, package internals and proprietary strings may still be present.

## Signals

The index currently recognizes:

- Expert/manual lens controls and 0.6×/15 mm/24 mm/50 mm values;
- Camera ID selection and physical-camera APIs;
- session/stream/request creation;
- MediaTek and Nothing routing vendor keys;
- SAT, logical-camera, multicamera and seamless-sensor terminology;
- widget, shortcut and intent parsing;
- state persistence and restoration;
- JNI/native boundaries;
- system-camera permissions and enforcement;
- candidate internal constants for IDs `2`, `3`, `4` and `5`.

## Bridge scoring

A file receives additional weight when it combines signals that may form part of one call chain. High-value combinations include:

```text
Expert UI + Camera ID selection
Expert UI + session construction
Expert UI + routing vendor key
SAT/multicam + routing vendor key
widget intent + state restoration
session construction + JNI/native call
```

These combinations prioritize likely controllers, repositories, factories and device adapters over isolated strings or resources.

## Review sequence

1. Start with `routeCandidateFiles` in the JSON output.
2. Identify the lens button/listener entry method for 0.6×, 1× and 2×.
3. Trace assignments into the selected-lens, focal or camera-route state object.
4. Follow that object into camera selection and session/request construction.
5. Record every Camera2, reflection, Binder and JNI boundary.
6. Add runtime hooks for indirect or obfuscated edges.
7. Compare static candidates with the controlled fresh-process route traces.

## Evidence boundary

A string or code-reference match establishes only that a symbol or value is present in the analyzed package. It does not prove that the path executes on Galaga, that it controls sensor selection, or that it is reachable by an ordinary application.

Causality requires:

- a working stock trace;
- route-specific arguments or state;
- controlled positive and negative reproduction;
- optical output verification.

## Automated tests

`tests/test_build_routing_index.py` verifies:

- ranking of a synthetic Expert UI → Camera2 session → MediaTek route bridge;
- selection of the newest static-analysis run.

The repository validation workflow compiles the tool and runs these tests automatically.
